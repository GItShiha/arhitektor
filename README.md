# Архитектор

Локальная мастерская для писателей: вселенные, общая энциклопедия, произведения и сцены.
Первый этап: Python 3.12+, PySide6 / Qt Widgets, SQLAlchemy 2.x, SQLite и Alembic.
Облачных сервисов, телеметрии и обязательных ключей API нет.

## Установка на CachyOS / Arch Linux

Системные пакеты (команда предназначена для вашего компьютера):

```bash
sudo pacman -Syu python python-pip libglvnd libxkbcommon fontconfig freetype2 dbus
# Для запуска через X11 / XWayland также:
sudo pacman -S libxcb xcb-util-cursor xcb-util-keysyms xcb-util-renderutil xcb-util-wm xcb-util-image
```

В каталоге репозитория:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
arhitektor
```

Для воспроизводимой установки при наличии `uv` используйте `uv sync --frozen --extra dev`
(версии и контрольные суммы зафиксированы в `uv.lock`).

Qt поставляется в PySide6 wheel; системный пакет PySide6 для venv не нужен.
На Wayland при необходимости явно выберите платформу:

```bash
QT_QPA_PLATFORM=wayland arhitektor
# Альтернатива через XWayland:
QT_QPA_PLATFORM=xcb arhitektor
```

Qt 6 поддерживает HiDPI автоматически. Дополнительный масштаб: `QT_SCALE_FACTOR=1.25`.
Шрифт берётся из системы. Проверка в настоящем KDE Plasma / Wayland пока не выполнена.

## Рабочее пространство

Три области изменяют ширину перетаскиванием разделителей. Слева выберите вселенную
(или «Все вселенные») и раздел: «Обзор», «Произведения», «Энциклопедия», «Персонажи»,
«Организации», «Локации». Хронология появится на следующем этапе. Ниже показаны объекты
текущего раздела и поиск по названиям; для статей поиск также учитывает текст и теги.
Кнопка «Назад» возвращает на предыдущий экран. Внизу слева доступны настройки и данные.

При выборе вселенной обзор показывает описание, реальные количества статей и произведений,
недавно изменённые объекты и действия создания. Кнопка «＋ Создать» создаёт вселенную,
статью, произведение или сцену. Произведение может существовать без вселенной.

Статья открывается как отдельная страница: заголовок и текст в центре, тип, теги и
произвольные дополнительные поля справа. Настройки вселенных и поля статей редактируются
вертикальными карточками в прокручиваемой панели без горизонтальной прокрутки. Каждое
поле можно добавить, переименовать, изменить или удалить. Короткий текст вводится в строке,
длинный — в расширяющемся по высоте редакторе; числа — счётчиками, логические значения —
флажками. Тип выбирается из списка. Вложенные объекты и списки редактируются в отдельном
широком диалоге без ручного JSON; «Отмена» сохраняет исходное значение. Пустые значения
и большие целые числа сохраняются без потери точности. Для целых вне диапазона Qt
используется точный десятичный ввод. Панель свойств имеет минимальную ширину 330 пикселей.

Произведение показывает список сцен; сцену можно открыть слева или со страницы рукописи.
Редактор сцены отображает счётчик слов. Кнопки «↑ Раньше» и «↓ Позже» меняют порядок.
«Скрыть свойства» убирает правую панель; «Режим письма» скрывает обе боковые панели.
Размеры панелей и видимость свойств сохраняются между запусками.

Сцена сохраняется через 700 мс после последнего изменения. Другие формы сохраняются
кнопкой / Ctrl+S и перед переходом. Приложение дожидается записи при переключении и
закрытии; при ошибке редактор остаётся открыт с несохранённым текстом. При внезапном
завершении процесса изменения за последний интервал автосохранения могут быть потеряны.

Удаление подтверждается. Удаление произведения удаляет сцены; удаление вселенной
удаляет её статьи, но сохраняет произведения и сцены без привязки к вселенной.

## Данные, копии и экспорт

База: `$XDG_DATA_HOME/arhitektor/library.sqlite3`, по умолчанию
`~/.local/share/arhitektor/library.sqlite3`. Относительный XDG_DATA_HOME игнорируется.
В этом же каталоге находится журнал с ротацией и файл блокировки второго экземпляра.
Пользовательские данные не размещаются в репозитории. Для отдельной тестовой библиотеки
задайте абсолютный `XDG_DATA_HOME`.

SQLite использует внешние ключи, WAL и `synchronous=FULL`. Каждая операция изменения
выполняется в транзакции; миграции Alembic применяются при запуске в рабочем потоке.
Перед будущими обновлениями рекомендуется создавать резервную копию.

Копия создаётся штатным SQLite backup API, включая зафиксированные изменения WAL,
и проверяется `integrity_check`. Для копии и экспорта выбирайте новое имя файла:
существующий файл не перезаписывается. Копии стоит дополнительно хранить на другом диске.

Восстановление: закройте приложение, сохраните весь текущий каталог данных в безопасное
место, затем положите копию под именем `library.sqlite3` в новый пустой каталог
`arhitektor` внутри выбранного XDG_DATA_HOME. Не смешивайте восстановленную базу со
старыми файлами `-wal` и `-shm`. Запустите приложение с тем же XDG_DATA_HOME.

Экспорт JSON UTF-8 содержит версию формата, дату и все четыре коллекции с идентификаторами,
связями, текстами и дополнительными полями. Запись файла атомарная. Импорт JSON пока не
реализован; для полного восстановления используйте SQLite-копию.

## Структура и решения

```text
src/arhitektor/
  app.py                        запуск, журнал, блокировка второго экземпляра
  models.py                     типизированные модели SQLAlchemy
  services.py                   транзакционные операции, поиск, копии, экспорт
  infrastructure/database.py    XDG, SQLite, запуск Alembic
  infrastructure/migrations/    версионируемая схема
  ui/window.py                  экраны, переходы и автосохранение
  ui/navigation.py              разделы, вселенные и контекстное дерево
  ui/properties.py              прокручиваемая панель свойств
  ui/field_editor.py            карточки полей и диалог вложенных значений
  ui/jobs.py                    последовательная очередь фоновых операций
  ui/theme.py                   тёмная тема
 tests/                         проверки данных и Qt без экрана
```

- `universes`: id, title, description, settings JSON, created_at, updated_at.
- `articles`: id, universe_id, title, kind, content, tags JSON, fields JSON, даты.
- `works`: id, nullable universe_id, title, kind, description, status, даты.
- `scenes`: id, work_id, title, content, position, word_count, даты.
  Пара `(work_id, position)` уникальна; позиции нормализуются транзакционно.

Слой операций возвращает обычные словари; ORM-сессии не пересекают границы потока.
Один рабочий поток сохраняет порядок операций. Qt-поток обновляет только интерфейс.
Типы — свободные строки, настройки и поля — JSON: простая база для будущих шаблонов.
Для связей, истории, глав и частей потребуются отдельные таблицы и миграции.
Методы планирования можно будет хранить отдельно от текста сцен, а локальный LLM-клиент
добавить отдельным модулем без зависимости моделей данных от LM Studio.

Пока библиотека загружается целиком, а поиск выполняется через Unicode casefold в фоне:
это решение для небольших локальных библиотек. Для больших объёмов следующим шагом
станут ленивое дерево и индекс поиска. Главы, таймлайн, история правок, ИИ, сложное
форматирование и EPUB/DOCX не входят в этот этап.

## Проверки

```bash
QT_QPA_PLATFORM=offscreen python -m pytest -q
python -m compileall -q src
ruff check src tests
```

Тесты проверяют навигацию и настройки панелей, миграцию, CRUD, откат транзакции, правила удаления, порядок сцен,
Unicode-поиск, XDG, счётчик слов, копирование WAL и открытие копии, JSON-экспорт,
автосохранение, переход между сценами, закрытие/открытие и отказ записи.
Offscreen-проверки не заменяют ручную проверку на KDE Wayland.

## Этап 3 — первый законченный срез: двусторонние связи

В карточке статьи раздел «Связанные объекты» позволяет создать связь с другой статьёй
той же вселенной. В диалоге задаются прямое и обратное названия отношения, цель можно
найти по названию и отфильтровать по типу. Например: «работает в» / «имеет сотрудника».
Одна запись отображается с обеих сторон, позволяет перейти к другой статье и удалить
связь без удаления статей. Удаление статьи очищает её связи. Повторная связь с тем же
направлением и названием (в том числе введённая с обратной стороны) отклоняется.

Миграция `0002` добавляет таблицу `article_relations`. Перед обновлением старой базы
создаётся проверенная копия `backups/pre-migration-*.sqlite3`. Ошибка копирования или
неизвестная версия схемы останавливает обновление. Миграция выполняется в транзакции.
Старые типы-строки, тексты, настройки и дополнительные поля сохраняются. Связи входят
в SQLite-копии и в коллекцию `relation` JSON-экспорта. Вертикальные карточки свойств,
редактор вложенных значений и автосохранение продолжают использоваться.

## Этап 3.2 — типы и шаблоны

В «Настройки и данные → Типы и шаблоны» выберите вселенную, затем существующий тип
или «Новый тип». Показано количество статей каждого типа. В диалоге можно изменить
название, добавить и удалить определения полей, изменить порядок стрелками, задать
тип, варианты выбора (по одному на строку) и значение по умолчанию. При сохранении
задаётся позиция типа в списке (с нуля). Шаблоны изолированы по вселенным.

Новая вселенная получает восемь обычных редактируемых типов. В новой статье тип
выбирается при создании; изменить его можно в правой панели существующей карточки.
Доступны короткий/длинный текст, целые/дробные числа, флажок, календарная дата,
выбор одного значения и ссылка на статью той же вселенной. Поля доступны для ввода сразу; любое редактирование задаёт значение.
Кнопка «Очистить» возвращает None. Для логических полей используется один список
«Не указано / Да / Нет» (None / True / False). Простое открытие не записывает
показанные в редакторах числа или даты. Пустая строка, 0 и False отличаются от None. По ссылке можно перейти к статье;
правки текущей карточки сохраняются перед переходом.

Миграция `0003` добавляет `article_templates` и nullable `articles.template_id`.
До обновления создаётся проверенная SQLite-копия штатным механизмом миграций.
Старые типы переносятся в шаблоны своей вселенной, старые значения `fields` не
перезаписываются. Встроенные разделы навигации сохраняют принадлежность старых типов
при их переименовании. Идентификатор нового поля — неизменяемый UUID, подпись и порядок
хранятся отдельно. Удалённые определения архивируются: введённые значения отображаются
как поля «вне шаблона». Смена типа статьи также сохраняет все значения. Несовместимое
изменение типа поля или сокращение списка выбора отклоняется, если оно обесценит
сохранённые значения. Изменение шаблона не подменяет значения старых статей новыми
значениями по умолчанию. Удаление самих типов не реализовано; статьи не удаляются.

JSON-экспорт теперь имеет `version: 2`: старые коллекции и их поля сохранены, добавлена
коллекция `template` с определениями и идентификаторами, а статьи содержат `template_id`.
Новые значения в `fields` связаны с UUID определений; прежние именованные ключи остаются
дополнительными полями. Потребителям версии 1 нужно учесть новую версию и коллекцию;
импорт JSON по-прежнему не поддерживается. SQLite-копия содержит всю новую структуру.

Ограничения: ссылочное поле не создаёт отдельной двусторонней связи автоматически;
для этого используется прежний раздел связей. При удалении цели сохранённая ссылка
показывается как недоступная, её можно очистить или заменить. Визуальный граф,
хронология и ИИ не реализованы. Проверки выполняются в Qt offscreen, без проверки
настоящего KDE Wayland.

## Уточнения UX 3.2.1

В энциклопедии доступна кнопка «Типы и шаблоны» — она открывает тот же редактор,
что и настройки, с учётом выбранной вселенной. Фильтр вселенной сохраняется между
запусками. В общем списке статьи дополнены названием вселенной, в конкретной
вселенной отображаются только её статьи. При создании статьи из общего списка
нужно явно выбрать вселенную; фильтрация не меняет данные и не создаёт копий.

В центре карточки «Основное описание» редактирует прежнее содержимое статьи.
Дополнительные многострочные поля подписаны отдельно и остаются в `fields`;
они не объединяются с основным текстом. Формат базы и миграции не изменялись.

## Пустые значения 3.2.2

Незаданные числовые поля отображаются пустыми: отдельный флаг отображения Qt spinbox
управляет форматированием текста, а модель продолжает хранить None. Никакое число
не зарезервировано как признак пустоты. Ввод 0 задаёт именно ноль; стрелки работают и
после очистки. Обработка потери фокуса не превращает пустое поле в число.

Для даты используется строка `дд.мм.гггг` с отдельным Qt-календарём. Это устраняет
автоматическое восстановление внутренней даты QDateEdit из пустого текста. В пустой
строке отображается подсказка «Не указано», а значение остаётся None. Открытие или
отмена календаря не задаёт дату: нужен явный выбор дня либо ввод корректной даты.
Некорректный ввод блокирует сохранение с понятным сообщением. Отдельные дублирующие
подписи «Не указано» удалены; списки содержат один соответствующий пункт.

Схема SQLite не менялась. Регрессионный тест
`test_clear_and_restart_record_json_null_in_sqlite` проверяет фактический JSON в SQLite,
очистку, ноль, выбор даты, повторное открытие базы и повторную очистку. Проверки выполнены
в Qt offscreen; поведение календарного окна на реальном KDE Wayland требует ручной проверки.
